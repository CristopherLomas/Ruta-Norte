02

Problemática Real vs Solución Implementada

Diagnóstico del transporte intercantonal en la sierra norte y valor del sistema

✕ Dolores del Sistema Tradicional

  • Sobreventa de Asientos: Registro manual en papel o planillas Excel descoordinadas entre terminales.
  • Invisibilidad de Tramos: Usuarios en cantones intermedios (Bolívar, El Ángel, Mira) desconocen horarios y disponibilidad real.
  • Fraude en Boletos: Tiquetes físicos sin validación criptográfica, propensos a duplicación o reutilización.
  • Cero Trazabilidad: Falta de manifiestos digitales y reportes centralizados de recaudación para la directiva.

✓ Solución Tecnológica Ruta Norte

  • Concurrencia Pesimista: Bloqueos atómicos de base de datos impiden vender dos veces el mismo asiento.
  • Tarifas y Tramos Dinámicos: Cobro justo por paradas intermedias con tiempos y distancias de carretera real.
  • Boleto QR Inviolable: Código con token firmado opaco (sin exponer datos personales) validado por inspectores en andén.
  • Auditoría & Despacho: Manifiestos en tiempo real, registro de averías mecánicas y analítica con Recharts.

Arquitectura del Sistema: Monolítica Modular

Monolito Modular de Alto Rendimiento — Next.js 14 App Router · 12 Módulos Bounded Context · Supabase PostgreSQL ACID

CAPA 1: PRESENTACIÓN Next.js App Router

Rutas por Rol & React Server Components

  • ▸ Route Groups por Rol: Segmentación estricta en (admin), (operator), (seller), (inspector), (passenger) y (public).
  • ▸ 85% Server Components: Renderizado en servidor con cero JS enviado al cliente en vistas maestras y TTFB instantáneo.
  • ▸ Catálogo UI shadcn/ui: Primitivas de interfaz accesibles WCAG 2.1 AA montadas sobre Radix UI y Tailwind CSS.
  • ▸ Cartografía Leaflet: Visualización de trazado vial real de la Panamericana E35 y andenes de abordaje.
Ubicación: src/app/ & src/components/
CAPA 2: DOMINIO 12 Módulos Bounded Context

Lógica Modular & Server Actions

  • ▸ Server Actions Atómicas: Mutaciones de negocio sin latencia de red interna ejecutadas directamente en el servidor.
  • ▸ Alta Cohesión Modular: 12 módulos autónomos (auth, trips, bookings, tickets, inspector, reports, etc.) con límites claros.
  • ▸ Validación Zod en el Límite: Reglas estrictas de cédula ecuatoriana, placas vehiculares y datos de entrada antes de persistir.
  • ▸ Cero Sobrecarga HTTP: Las Server Actions actúan como RPC en proceso eliminando serialización JSON redundante.
Ubicación: src/features/
CAPA 3: PERSISTENCIA PostgreSQL 15+ ACID

Base Relacional & RLS Perimetral

  • ▸ 18 Tablas Relacionales: Integridad en 3NF con claves UUID v4 y cascadas de eliminación protegidas.
  • ▸ Row Level Security (RLS): Políticas activas en cada tabla verificando el rol del usuario mediante auth.uid().
  • ▸ Triggers de Expiración (10 min): Liberación automática de asientos reservados si no se confirma el pago simulado.
  • ▸ Migraciones Versionadas: Scripts SQL estructurados (001 a 008) y dataset maestro determinista en seed.sql.
Ubicación: supabase/migrations/ & supabase/seed.sql

⚡ Cero Latencia de Red Interna

Las operaciones de negocio entre el frontend y el backend se ejecutan en proceso mediante Server Actions, sin saltos de red HTTP adicionales ni serialización JSON repetitiva.

🔒 Type Safety de Extremo a Extremo

TypeScript estricto unifica el modelo relacional, las Server Actions y las vistas de usuario, eliminando errores de desincronización de contratos DTO entre capas.

🚀 Despliegue Atómico y Mantenible

Una sola unidad de despliegue en Vercel garantiza compatibilidad absoluta de versiones en cada release, simplificando CI/CD y reduciendo costos operativos.

04

Arquitectura de la Aplicación

Patrón monolítico modular, límites de hidratación y ciclo de vida de mutaciones

1. Monolito Modular

Un único repositorio cohesivo con módulos aislados en src/features/. Evita la complejidad y latencia de microservicios, permitiendo transacciones ACID directas en base de datos.

2. 85% Server Components

El 85% del código se ejecuta exclusivamente en el servidor. Reduce a cero el JavaScript innecesario en el navegador, protege la lógica de negocio y ofrece TTFB instantáneo.

3. Sesión con Cookies HttpOnly

Sin uso de localStorage. Sesiones administradas mediante cookies cifradas con flags HttpOnly, Secure y SameSite=Lax inmunes a ataques XSS.

Catálogo de Operaciones y Endpoints del Monolito Modular

Mapeo de Server Actions (RPC de alta velocidad en proceso) y Route Handlers RESTful por módulo

Módulo & Operación Mecanismo / Ruta Contrato de Entrada (Zod) Seguridad / RBAC Efecto en Dominio & PostgreSQL
auth / loginAction Server Action / POST loginSchema { email, password } Público Valida credenciales en Supabase Auth, emite JWT y establece cookies HttpOnly protegidas.
trips / searchTripsAction Server Action / GET { originId, destId, date } Público Consulta viajes programados, calcula tramos intermedios de la ruta E35 y cupos disponibles.
trips / getTripSeatsAction Server Action / RPC { tripId: UUID } Público Genera matriz gráfica de asientos (30/40/44) marcando estados libre, reservado temporal o vendido.
bookings / createBookingAction Server Action Atómica createBookingSchema { tripId, seatIds } Autenticado / Taquilla Aplica transacción con bloqueo exclusivo en booking_seats y crea reserva temporal a 10 min.
bookings / cancelBookingAction Server Action Atómica { bookingId: UUID } Usuario / Operador Cancela reserva activa, libera asientos en booking_seats e incrementa available_seats.
payments / processPaymentAction Server Action Transaccional paymentSchema { bookingId, method } Pasajero / Vendedor Registra pago simulado, confirma reserva, emite boletos y genera tokens QR criptográficos.
inspector / validateTicketAction Server Action & REST Route validateSchema { qrPayload } INSPECTOR / ADMIN Descifra token opaco, valida viaje y fecha, actualiza estado a used y previene doble abordaje.

09

Decisiones Técnicas de Arquitectura (ADRs)

Respuestas formales a los problemas de ingeniería más complejos

ADR-001

Concurrencia Pesimista

Uso de SELECT ... FOR UPDATE en PostgreSQL para bloquear asientos en el momento de la reserva. Si dos usuarios eligen el mismo asiento, la segunda transacción se aborta de forma segura.

Cero sobreventa garantizada
ADR-002

Token QR sin PII

El código QR solo codifica un token opaco RN-HEX16. Si alguien toma una foto al boleto no puede ver nombres ni cédulas. Solo el inspector autenticado accede a los datos al validar.

Protección de datos personales
ADR-003

Ruteo Vial Desacoplado

Patrón Strategy con RoutingProvider. El cálculo sigue la carretera E35 con OSRM y OpenStreetMap a costo $0, sin atarse rígidamente a Google Maps ni trazar líneas rectas irreales.

Soberanía y costo $0
