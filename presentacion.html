Problemática Real vs Solución Implementada

Diagnóstico del transporte intercantonal en la sierra norte y valor del sistema

✕ Dolores del Sistema Tradicional

  • Sobreventa de Asientos: Registro manual en papel o planillas Excel descoordinadas entre terminales.
  • Invisibilidad de Tramos: Usuarios en cantones intermedios (Bolívar, El Ángel, Mira) desconocen horarios y disponibilidad real.
  • Fraude en Boletos: Tiquetes físicos sin validación criptográfica, propensos a duplicación o reutilización.
  • Cero Trazabilidad: Falta de manifiestos digitales y reportes centralizados de recaudación para la directiva.

✓ Solución Tecnológica Ruta Norte

  • Concurrencia Pesimista: Bloqueos atómicos de base de datos impiden vender dos veces el mismo asiento.
  • Tarifas y Tramos Dinámicos: Cobro justo por paradas intermedias con tiempos y distancias de carretera real.
  • Boleto QR Inviolable: Código con token firmado opaco (sin exponer datos personales) validado por inspectores en andén.
  • Auditoría & Despacho: Manifiestos en tiempo real, registro de averías mecánicas y analítica con Recharts.

División Clara: Frontend vs Backend

Separación de responsabilidades, tecnologías de cada lado y puente de comunicación

CAPA CLIENTE (FRONTEND) Ejecutado en el Navegador

Interfaz de Usuario e Interactividad

  • ▸ Componentes Cliente ('use client'): Solo en hojas interactivas (mapa Leaflet, selector de asientos, modal escáner de cámara QR).
  • ▸ Estilos & UI Primitives: Tailwind CSS + shadcn/ui sobre Radix UI accesible (WCAG 2.1 AA) sin runtime pesado.
  • ▸ Cartografía Interactiva: Leaflet canvas con renderizado de polilíneas viales, popups de paradas y zoom fluido.
  • ▸ Manejo de Formularios: React Hook Form sincronizado con validadores Zod y estados reactivos a 60 FPS.
  • ▸ Cero Secretos: Solo conoce la anon_key pública de Supabase; nunca accede a claves maestras.
Archivos clave: components/ui/*, components/shared/*, lib/maps/InteractiveMap.tsx, features/inspector/components/QrScannerClient.tsx
CAPA SERVIDOR & DATOS (BACKEND) Servidor Node.js / Edge + PostgreSQL

Lógica de Dominio, Seguridad y Persistencia

  • ▸ React Server Components (RSC): Renderizado en servidor sin enviar JavaScript al cliente; consulta directa a la BD.
  • ▸ Server Actions ('use server'): Endpoints de mutación tipados (RPCs) que procesan reservas, pagos, cancelaciones y validaciones.
  • ▸ Edge Middleware: Control perimetral de sesiones con @supabase/ssr y cookies seguras HttpOnly.
  • ▸ Motor de Base de Datos ACID: PostgreSQL 15+ con funciones PL/pgSQL transaccionales y bloqueos FOR UPDATE.
  • ▸ Seguridad Nativa RLS: Políticas de Row Level Security que restringen consultas a nivel de motor de datos.
Archivos clave: features/*/actions/index.ts, lib/supabase/server.ts, middleware.ts, supabase/migrations/*

Arquitectura de la Aplicación

Patrón monolítico modular, límites de hidratación y ciclo de vida de mutaciones

1. Monolito Modular

Un único repositorio cohesivo con módulos aislados en src/features/. Evita la complejidad y latencia de microservicios, permitiendo transacciones ACID directas en base de datos.

2. 85% Server Components

El 85% del código se ejecuta exclusivamente en el servidor. Reduce a cero el JavaScript innecesario en el navegador, protege la lógica de negocio y ofrece TTFB instantáneo.

3. Sesión con Cookies HttpOnly

Sin uso de localStorage. Sesiones administradas mediante cookies cifradas con flags HttpOnly, Secure y SameSite=Lax inmunes a ataques XSS.

Decisiones Técnicas de Arquitectura (ADRs)

Respuestas formales a los problemas de ingeniería más complejos

ADR-001

Concurrencia Pesimista

Uso de SELECT ... FOR UPDATE en PostgreSQL para bloquear asientos en el momento de la reserva. Si dos usuarios eligen el mismo asiento, la segunda transacción se aborta de forma segura.

Cero sobreventa garantizada
ADR-002

Token QR sin PII

El código QR solo codifica un token opaco RN-HEX16. Si alguien toma una foto al boleto no puede ver nombres ni cédulas. Solo el inspector autenticado accede a los datos al validar.

Protección de datos personales
ADR-003

Ruteo Vial Desacoplado

Patrón Strategy con RoutingProvider. El cálculo sigue la carretera E35 con OSRM y OpenStreetMap a costo $0, sin atarse rígidamente a Google Maps ni trazar líneas rectas irreales.

Soberanía y costo $0
